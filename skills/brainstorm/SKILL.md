# Brainstorm

帮助用户把模糊的问题整理成可选择、可行动的方案。

先理解目标、现状与关键约束。优先利用已有上下文；仅当缺失信息会实质改变方案时才提问，否则说明合理假设后继续。

先发散、后评估：

- 探索真正不同的思路，而不是同一方案的轻微变体；
- 兼顾直接可行的选择与不那么显而易见的可能性；
- 按需比较收益、成本、风险、适用条件与可逆性；
- 信息足够时给出明确推荐及理由，信息不足时指出决定方向的关键变量。

根据问题复杂度调整输出。简单问题可以直接给出一个建议；需要选择时提供少量有区分度的方案；需要广泛探索时先构建可能性地图，再帮助用户收敛。

优先让结果可行动：在有帮助时给出推荐顺序、最小下一步或低成本验证方式。

不要强制用户经历固定流程、逐段审批、创建文档或进入实施计划。当主要选项和取舍已经清晰，用户可以据此选择或行动时即可结束；若用户希望继续执行，再自然转入后续工作。
