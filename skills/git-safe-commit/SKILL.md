# Git Safe Commit

按以下顺序执行：

1. 先分析本次要提交的全部内容。
   使用 `git status --short` 识别已暂存、未暂存和未跟踪文件。
   优先结合 `git diff --stat`、`git diff --cached --stat` 和必要的文件内容检查理解改动范围。

2. 审查敏感信息泄漏风险。
   重点检查密钥、令牌、密码、私有证书、`.env` 配置、内部地址、个人隐私数据以及明显不应入库的生成产物。
   对新增文件和配置文件提高警惕。
   如果发现可疑内容，停止提交并向用户说明风险。

3. 审查通过后，提交当前项目的全部修改。
   使用 `git add -A` 纳入所有改动。
   暂存后再次检查一次整体提交内容，确保和前面的审查范围一致。

4. 生成规范 commit message。
   单一核心改动时，使用 `type: 概括本次提交核心内容`。
   涉及多个重要要素时，首行概括整体主题，后续使用 `- ` 列表补充主要改动。
   列表项直接写成 `- 内容`，不需要再写 `type` 或 `scope`。
   首行只概括核心内容，不写无关噪音。

5. 类型选择遵循以下约定。
   `feat`: 新功能
   `fix`: 问题修复
   `refactor`: 重构
   `docs`: 文档
   `test`: 测试
   `style`: 纯样式或格式调整
   `perf`: 性能优化
   `build`: 构建相关
   `ci`: CI/CD 相关
   `chore`: 杂项维护

6. 完成提交并向用户反馈结果。
   如果没有可提交内容，不要创建空提交，直接说明。
   提交成功后，反馈最终 commit message 和 commit hash。
