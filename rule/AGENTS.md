# AGENTS

## 项目 AGENTS.md 初始化

- 当项目根目录下没有 `AGENTS.md` 时，应结合用户要求和项目实际内容，利用自带的 `/init` 命令生成一份初始的项目级 `AGENTS.md`。
- 生成前应先查看项目结构、主要配置、构建测试命令和已有约定；生成内容应简洁、具体、可执行，避免套用与项目无关的模板说明。

## 语言使用规范

- 除非用户明确要求使用其他语言，否则生成的说明、文档等内容默认使用简体中文表述。

## 代码修复原则

- 在修复代码问题时，应先分析并找出问题根因，再实施修改。
- 修复方案应尽量优先选择小成本、低侵入的修改方式，避免不必要的大范围重构。

## 编码行为准则

- 先想清楚再编码：明确假设、权衡和关键歧义，必要时先提问。
- 简单优先：只实现明确需要的能力，不主动添加额外功能、配置或抽象。
- 精准修改：只改任务必需的代码，不顺手重构、格式化或改善无关内容。
- 只清理自己的改动：移除本次产生的死代码和未使用项，不擅自删除既有无关代码。

## 工具能力

### 飞书能力

- 当任务需要使用飞书 / Lark 能力时，应优先使用本机已安装的 `lark` CLI。
- 使用前可先查看 `lark` CLI 的帮助信息和当前登录状态；不要假设远程接口、凭据或工作区配置已可用。

## 本地环境

- 如果需要在本地运行项目或工具，应先检查当前默认环境是否已经具备所需依赖。
- 如果默认环境没有现成依赖，不要尝试在默认环境安装任何依赖。
- 默认环境不满足时，应检查 Codex 本地缓存的运行时是否能够支持当前任务。
- 如果缓存运行时仍不支持，应改用 conda 的 `self-use` 环境。
- 如果 `self-use` 环境中没有相关依赖，应先向用户请求在该环境中安装对应依赖；获得确认后再安装或运行。
- 若用户已明确给出应使用的 conda 虚拟环境，应优先在该环境下执行相关操作。
