# AGENTS

## 语言使用规范

- 除非用户明确要求其他语言，否则回复、说明和文档默认使用简体中文。

## 内容完善原则

- 完善方案、文档等内容时，从整体目标、结构和上下文审视反馈，统一调整受影响的内容，避免逐条追加补丁造成割裂、重复或矛盾；整体审视不意味着无关重写。

## 编码行为准则

- 先想清楚再编码：理解需求和现有实现，明确关键假设与权衡；无法从上下文消除、且影响目标或关键方案的歧义，先向用户确认。
- 简单优先：以满足需求的最小完整实现为准，不添加无明确需要的功能、配置或抽象。
- 精准修改：只改完成任务所必需的内容，不顺手重构、格式化或改善无关代码。
- 只清理自己的改动：移除本次改动产生的死代码和未使用项，不擅自删除既有无关代码或覆盖用户已有修改。

## 避免过度防御性编程

- 依据真实调用关系、类型契约和明确需求编写代码，不为臆测场景添加防御分支，也不为未要求支持的版本、格式或环境添加兼容逻辑。
- 在外部输入和系统边界进行必要校验；内部代码遵循已有契约，避免重复校验，保留必要的安全与数据完整性保障。
- 错误按项目约定明确传播并保留必要上下文，不通过宽泛的 try/catch、静默吞错或无依据的默认值掩盖异常。
- 仅在业务明确允许、且恢复行为有清晰语义时添加降级或兜底。
- 优先修复根因，不通过增加特殊分支绕过问题。

## 工具能力

### 飞书能力

- 当任务需要使用飞书 / Lark 能力时，应优先使用本机已安装的 `lark` CLI。
- 使用前可先查看 `lark` CLI 的帮助信息和当前登录状态；不要假设远程接口、凭据或工作区配置已可用。

## 本地环境

- 用户已明确指定环境时，优先使用该环境。
- 未指定环境时，先检查当前默认环境是否具备所需依赖；若不满足，再检查 Codex 本地缓存运行时。
- 不擅自在默认环境安装或升级依赖。
- 现有环境均无法满足时，说明缺失依赖和建议的处理方式，等待用户确认后再进行环境变更。
